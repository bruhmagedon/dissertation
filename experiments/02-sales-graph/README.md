# 02. Общая выборка и отложенные вычисления

Продажи `[10, 20, 30, 40]`, начальный порог `10`. Фильтр включает продажи,
равные порогу: `sale >= minimum`.

Граф: `threshold → filtered → sum, count → average`.
Оба агрегата читают один и тот же `filtered`. Каждый сценарий создаёт новый граф.
Нет `effect`, дополнительных реактивных чтений для журнала и измерения времени.
Строка `computed` отмечает вход в функцию; её зависимости могут вычисляться дальше.

## Запуск из корня репозитория

Нужен Node.js 22.18+ с поддержкой запуска TypeScript без сборки и pnpm 11.

```bash
pnpm --dir experiments/02-sales-graph install --frozen-lockfile
pnpm --dir experiments/02-sales-graph start
```

После выполнения обоих сценариев `deepStrictEqual` отдельно проверяет сохранённые
результаты: A — `[25, 30, 35, 35]`, B — `[25, 35, 35]`.
Счётчики увеличиваются только внутри функций `computed`. Консоль выводит фактические
счётчики; регрессионные тесты дополнительно проверяют наблюдавшиеся числа вызовов.

## Одностраничный интерфейс

```bash
pnpm --dir experiments/02-sales-graph dev
```

Откройте адрес сервера, обычно `http://127.0.0.1:5173`.
Vite+ запускается локальным `vp`; глобально устанавливать его не нужно.

Интерфейс использует shadcn/ui с пресетом `bKsEuMcK`: Radix Luma, база Stone,
Inter и янтарный основной цвет. Тема находится в `src/theme.css`, конфигурация —
в `components.json`; кнопки, поле ввода, метки и фильтр используют компоненты из
`src/components/ui/`. При необходимости повторно применить пресет из папки эксперимента:

```bash
pnpm exec vpx shadcn@latest apply --preset bKsEuMcK --yes -c .
```

- Ручной граф начинается с порога 10, без чтений и вычислений.
- «Записать» меняет только порог, «Прочитать среднее» явно читает результат.
- «Запустить A/B» выполняет исходный сценарий на свежем графе.
- React Flow показывает фиксированные зависимости; доступны панорамирование и масштаб.
- На узлах показаны сохранённые значения и реальные счётчики. После записи показано,
  что значения относятся к предыдущему чтению.
- Журнал можно фильтровать, прокручивать и просматривать снимок любого события.
- «Скачать TXT» экспортирует полный текущий журнал в `reactivity-journal.txt` (UTF-8),
  независимо от выбранного фильтра, без чтения signals и изменения счётчиков.
- Пустая выборка даёт `null` («Нет продаж»), а не `NaN`; порог должен быть конечным числом.

`experiment.ts` — общий вычислительный код для `script.ts` и SPA. Signals закрыты внутри
`createExperiment()`. Каждая операция записывает вход, вызовы функций, их возвращённые
значения и результат чтения. `snapshotFromJournal()` восстанавливает обычные данные
из журнала, не обращаясь к signals. React получает эти снимки после команд.
У графа и просмотра журнала нет доступа к реактивным значениям, подписок или signals `effect`.
React `useEffect` в `Graph.tsx` только подгоняет холст при изменении его размеров.

## Зависимости и порядок чтения

Над полотном — переключатель «Зависимости / Порядок чтения». В режиме зависимостей
каждый реактивный узел представлен одной карточкой. В режиме чтения выберите строку
операции в журнале: каждая записанная операция чтения представлена отдельной
карточкой с её ID. Карточки расположены сверху вниз по времени начала, отступом
показана глубина, а стрелка связывает конкретный запрос с его родителем.

При первом чтении дерева шесть карточек: Среднее, Сумма, Выборка, Порог,
Количество, Выборка. Стрелка от Среднего к Количеству соединяет родительский запрос,
хотя Порог предшествует Количеству в хронологии. Обе карточки Выборки — обращения
к одному `computed`: первое выполняет фильтрацию, второе получает готовое значение.
Стрелка к готовому значению пунктирная. Сводка над графом отдельно показывает число
обращений к узлу, вычисления за выбранную операцию и общее число за прогон.

Журнал записывает `read-start` / `read-end` вокруг каждого существовавшего чтения
`.value`, включая внешнее чтение среднего. У запроса есть ID и родитель; события
начала и завершения тела `computed` связаны с активным запросом. Из этих событий
строится дерево без дополнительных чтений, `peek` или `effect`. Когда Preact
вызывает `computed` во время проверки зависимостей без отдельного явного чтения,
в дереве появляется карточка «Проверка зависимости». Это зафиксированное выполнение,
а не придуманный запрос; чтения внутри этого тела связываются с этой карточкой.

«Вся операция» показывает все карточки. «Вперёд / Назад» открывают их по порядку
на тех же позициях. Значение и прирост появляются после завершения события. Каждый
шаг включает завершения до следующего начала, последний — до конца операции.
Карточки и сводка показывают выбранный момент; таблица под графом — текущий прогон.
Запись порога показывается отдельной карточкой с новым значением и нулём вычислений.
Повторное чтение при 30 показывает одну карточку Среднего со значением 35 и статусом
«Готовое значение».

```bash
cd experiments/02-sales-graph
```

`build` проверяет TypeScript и создаёт production-сборку через Vite+.
Шесть проверок общего модуля покрывают сценарии, ленивые вычисления, повторные
чтения, изоляцию снимков, чистый просмотр истории, пустую выборку, порядок и родство
обращений, готовые результаты и счётчики завершений по кадрам.

Playwright запускает production-сборку в Chromium. Для эталона отдельным процессом
запускается `node script.ts --json`. Ручные действия A/B и кнопки сценариев сравниваются
с консолью по результатам, всем четырём счётчикам и полному журналу.
Отдельная проверка двигает и масштабирует холст, прокручивает и фильтрует журнал,
открывает снимок события после записей 20 и 30, когда новый результат ещё не прочитан.
Она проверяет неизменность журнала и счётчиков, затем делает явные чтения и снова
сравнивает полный журнал с консольным B: скрытые вычисления тоже обнаружились бы.
Проверяются сброс, мобильная ширина и отсутствие ошибок браузера.
Всего 10 браузерных проверок. Проверяются шесть карточек первого чтения, две карточки
выборки, родительские связи, пунктир готового результата, навигация по завершениям,
нулевая стоимость записи и повторного чтения, проверки зависимостей и различие A/B.
После просмотра истории, переключений режима и перемещения обоих вариантов графа
делается явное чтение: полный журнал снова сравнивается с эталоном, чтобы обнаружить
и скрытые обращения, которые могли бы не отразиться в старом снимке экрана.
Снимки экрана создаются в `screenshots/`.

Если Chromium установлен локально в `node_modules/.cache/ms-playwright`,
а библиотеки доступны в snap-пакетах, их можно подключить при запуске:

## Размер набора в сравнении

В «Сравнить прогоны» выберите 4, 1 000, 10 000, 100 000 или своё целое число
от 2 до 100 000, затем нажмите «Запустить сравнение». В обоих режимах на свежих
графах повторяются записи и чтения текущего прогона. Чтобы сравнить 11 → 12,
сначала запишите 11 и прочитайте среднее, затем запишите 12 и прочитайте снова.
Для 10 → 11 используйте такую же последовательность с соответствующими порогами.

Размер в поле — настройка следующего запуска. Карточки сохраняют размер,
результаты, количество строк выборки и счётчики завершённого сравнения.
Клик по операции переносит её сохранённый журнал и размер набора на полотно.

Для четырёх продаж остаётся `[10, 20, 30, 40]`. Остальные размеры создаются
детерминированно: `[10, 12, 13, …, N + 10]`. На больших наборах журнал хранит
размер массива и первые пять значений, а вычисления работают с полными массивами.
Поэтому просмотр графа и экспорт TXT не разворачивают десятки тысяч строк.
Серийные замеры для продаж не выполняются.

### Входы, результаты и кеши

- Генератор сохраняет набор, порядок и дубликаты имён по seed. В пресетах
  сотрудники для редактирования выбираются из текущей страницы. Доступны
  размеры 100, 1 000, 10 000 и именованный набор из трёх сотрудников.
- Поиск применяется после нажатия «Найти» или Enter. Поиск, фильтр и сортировка
  сбрасывают номер страницы. При сокращении выборки отображаемый номер
  ограничивается последней существующей страницей. При пустой выборке
  возвращаются пустые строки и ноль страниц.
- Справочник имён и должностей, принадлежность к отделам и телефоны разделены.
  Телефон меняет только карту телефонов. Сортировка одинаковых имён сохраняет
  порядок по ID в обоих направлениях. Перевод сотрудника может сохранить
  отбор, при этом обновить и строки, и открытую сводку.
- Preact использует сигналы на тех же входах, которые Reselect читает из
  иммутабельного снимка. Preact отслеживает зависимости вычислений, Reselect
  использует отдельные `lruMemoize` для аргументов и функций результата, оба
  с `maxSize: 1`. Дополнительный `resultEqualityCheck` настраивается только
  для функции результата выбранного селектора. Версии зафиксированы в lockfile.
- Для отбора и страницы равны только ID одинаковой длины в том же порядке.
  Для сводки сравниваются все пары «отдел — число» в фиксированном порядке.
  Из четырёх политик три включают ровно одну проверку и возвращают прежний
  объект при совпадении. У сводки в этом графе нет вычисляемых потомков.
- Прямой расчёт на плоском массиве проверяет полные строки, порядок ID,
  сведения о странице и запрошенную сводку после каждого действия.
  Расходящийся вариант исключается из измерения. Снимки полотна и журнала
  формируются в диагностическом прогоне и читаются без обращения к кешу.

### Сравнение архитектур и условий

В A отбор получает карту отделов напрямую. В B промежуточный узел возвращает
карту для выбранного отдела и стабильный `null` для «Все отделы». В Preact
это позволяет `computed` отбора сохранить результат, в Reselect сохраняются
значения входов функции результата. Сам промежуточный узел может выполниться
после перевода. Строки и открытая сводка в обоих графах читают карту отделов
напрямую.

В разделе **Одни переводы, разные условия** две записи меняют только
запрос сводки или фильтр. Выбранные люди начинают на первой странице обоих
условий, каждый перевод адресует нового сотрудника. Каждая запись проверяется
по своим запрошенным выходам. Кнопка **Открыть обе трассы** ведёт к первому
различию, а при совпадении показывает первое действие.

### Запись, серии и прогноз

JSON записи версии 1 содержит `data` с именованным набором или размером
и seed, `initial` с начальным видом, `steps` с внешними действиями
и явно запрошенными выходами. В серии версии 1 добавляются состояние серии,
проверка корректности, параметры, среда и времена отдельных воспроизведений
с номерами парных повторов и порядком политик. Сборка указывается с отпечатком
измеряемого кода и lockfile. Отменённая серия остаётся доступна для экспорта
с частичным результатом.

```bash
pnpm --dir experiments/02-sales-graph research --profile editing --size 1000 --seed 42 --out editing.json
pnpm --dir experiments/02-sales-graph research --profile departments --size 1000 --seed 42 --engine reselect --extended --out departments.json
```

Для одного графа CLI принимает `--graph A` или `--graph B`. Флаг
`--architecture` запускает общий повтор для A0, A1, B0 и B1.
Старый JSON серии без поля `graph` открывается как A. Новый прогноз
сохраняет граф и проверяется на нём. `--forecast-out` фиксирует
калибровку и заранее определённую отложенную запись в отдельном JSON до замера.

Пути `--out` и `--input` задаются относительно каталога стенда. `--session 1`
выбирает другое воспроизведение пресета, `--threshold` меняет практический порог
в мс на запись. Отчёт CLI можно открыть через **Импорт серии**. Браузерные и
Node-серии имеют разные паспорта и не сводятся в одну выборку.

Таймер включает все записи состояния и запрошенные чтения в блоке. Создание
графа, первое чтение, эталон, журнал и отрисовка находятся вне интервала.
Каждое измерение воспроизводит весь блок на свежем графе после начального
чтения. Для оценки одного повтора усредняются 4 записи в пилоте или 6
в расширенной серии. Пилот использует 5 парных повторов и 3 прогрева,
расширенная серия — 25 и 6. Порядок политик перемешивается воспроизводимо.
Разница «базовая минус кандидат» считается внутри повтора. Отчёт выводит
медиану и квартили, после 12 пар — 95%-й процентильный интервал бутстрэпа
медианы по 2 000 выборкам пар. Практический порог по умолчанию 0,05 мс
на запись. Пилот описывает наблюдавшиеся значения, включая разброс. Частичные
серии и серии без достаточного числа полных пар получают статус «Недостаточно
данных для вывода». Практическая эквивалентность требует, чтобы интервал целиком
лежал внутри заданного порога. Если интервал допускает практически разные
исходы, вывод остаётся неопределённым.

Модель сравнивает результаты узла только при его выполнении и учитывает
совпадение с предыдущим результатом. По изменившимся аргументам она оценивает,
какие наблюдавшиеся функции могли бы не исполниться. Функция с несколькими
путями учитывается один раз. Другой изменившийся аргумент сохраняет необходимость
выполнения. Калибровка повторяет чистые функции на сохранённых входах вне
реактивного графа. Оценка вычитает стоимость компаратора, не оценивает обход
графа, накладные расходы кешей и эффекты памяти. Случаи с отложенным пересчётом
оцениваются приближённо. В проверке цена выбора считается относительно политики
с минимальной наблюдавшейся медианой и сопровождается интервалом, когда пар
достаточно. Для оценки переноса между движками выполните прогноз и проверку
на той же записи в каждом движке отдельно.
